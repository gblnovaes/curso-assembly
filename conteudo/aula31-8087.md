## O soquete vazio

Abra um IBM PC de 1981 e olhe a placa-mãe: ao lado do 8088 há um **soquete vazio** do mesmo tamanho. Ele era para o **8087**, o coprocessador matemático da Intel. Quem precisava fazer contas com números reais (engenharia, estatística, CAD, planilhas pesadas) comprava o chip à parte e encaixava ali.

O 8086 só sabe fazer contas com **inteiros**. Para calcular a área de um círculo, um programa sem coprocessador precisa de uma biblioteca em software que monta cada número real em várias words e faz a soma, a multiplicação e a divisão "na mão", com dezenas de instruções inteiras para cada operação. Com o 8087, uma multiplicação de reais vira **uma instrução** de cerca de uma centena de ciclos.

:::anos90 "Tem coprocessador?"
Durante os anos 80 e o começo dos 90, o coprocessador era um opcional caro: 8087 para o 8086/8088, 80287 para o 286, 80387 para o 386. Os programas perguntavam na instalação se havia um, e muitos tinham duas versões das rotinas de cálculo: uma para o chip e outra que **emulava** o chip em software. Só com o 486DX o coprocessador passou a vir dentro do processador, e a partir do Pentium ele virou parte de todo PC.
:::

O formato de números do 8087 deixou uma herança enorme: o padrão **IEEE 754**, publicado em 1985, nasceu em boa parte do trabalho feito para esse chip. O `float` e o `double` que você usa em C, Java ou JavaScript hoje seguem o mesmo padrão.

## Dois processadores, um programa

O 8087 não tem um programa próprio: ele lê as **mesmas instruções** que o 8086, no mesmo barramento. Os dois trabalham assim:

```diagrama titulo="8086 e 8087 lendo o mesmo código"
   memória:  ... MOV AX,5 │ 9B │ D9 06 00 00 │ ADD BX,AX ...
                          │    └─ ESC (D8h..DFh): instrução do 8087
                          └─ WAIT: o 8086 espera o 8087 ficar livre

   8086: busca tudo. Executa MOV e ADD. Num ESC, só calcula o
         endereço do operando e faz uma leitura "de mentira",
         para o 8087 pegar o endereço no barramento.
   8087: observa o barramento. Ignora MOV e ADD. Num ESC,
         decodifica a instrução e faz a conta, enquanto o
         8086 já segue para a próxima instrução.
```

- Toda instrução do 8087 começa com um opcode de **D8h a DFh**, chamado **ESC** (escape). Para o 8086, é quase um NOP: ele calcula o endereço efetivo e segue em frente.
- O 8087 trabalha **em paralelo**. Enquanto ele divide, o 8086 pode continuar executando instruções inteiras.
- Para não atropelar o 8087 (mandar uma nova instrução antes de a anterior terminar), existe a instrução **WAIT** (também escrita **FWAIT**, opcode 9Bh): o 8086 para até o 8087 avisar, por um pino, que está livre.

No 8087, o programa é responsável por esse sincronismo. Por isso o MASM e o TASM, montando para o 8087, colocam um **9Bh antes de cada instrução do coprocessador**. Abra a listagem no laboratório e você vai ver: `FLD raio` vira `9B D9 06 ..`. As formas que começam com **FN** (`FNINIT`, `FNSTSW`, `FNSTCW`...) são as versões "sem espera", sem o 9Bh.

:::atencao O FWAIT que o montador não coloca
O 9Bh automático vem **antes** de cada instrução do 8087. Mas quando o 8087 grava um resultado na memória (`FSTP x`) e logo depois o **8086** lê essa variável (`MOV AX,x`), não há nenhuma instrução do 8087 no meio, e portanto nenhum WAIT. O 8086 pode ler a memória antes de o 8087 terminar de escrever. A regra: **antes de o 8086 ler um resultado do 8087, coloque um `FWAIT`**. O simulador executa tudo na ordem e não reproduz esse erro, mas o hábito vale para o hardware de verdade.
:::

## A pilha de registradores

O 8087 tem **oito registradores** de 80 bits, mas eles não têm nomes fixos como AX e BX. Eles funcionam como uma **pilha**: o topo se chama **ST** ou **ST(0)**, o de baixo **ST(1)**, e assim por diante até **ST(7)**.

```diagrama titulo="FLD empilha, FSTP desempilha"
   FLD a          FLD b          FADD           FSTP soma
 ┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐
 │ ST(0)=a│     │ ST(0)=b│     │ST(0)=a+b     │ (vazia)│
 │ vazio  │     │ ST(1)=a│     │ vazio  │     │        │
 │ vazio  │     │ vazio  │     │ vazio  │     │        │
 └────────┘     └────────┘     └────────┘     └────────┘
                                              soma = a+b na memória
```

Por dentro, os oito registradores físicos ficam fixos e um campo de 3 bits da palavra de status, o **TOP**, aponta qual deles é o topo. `FLD` decrementa TOP e grava; `FSTP` lê e incrementa TOP. Por isso ST(1) "vira" ST(0) depois de um pop: os dados não se movem, só o ponteiro.

Duas regras para não se perder:

- **Equilibre a pilha** como você equilibra PUSH e POP. Cada `FLD` precisa de um `FSTP` (ou de uma operação com P) correspondente.
- A pilha tem só **oito lugares**. Um nono `FLD` causa **estouro da pilha**, e ler um registrador vazio causa **pilha vazia**. Nos dois casos o 8087 liga a exceção de operação inválida e o valor vira "indefinido" (NaN). O simulador avisa quando isso acontece.

:::cpu 80 bits por dentro
Cada registrador do 8087 tem **80 bits**: 1 de sinal, 15 de expoente e 64 de mantissa (o formato "real temporário", ou *extended*). Todas as contas são feitas com essa precisão, e o arredondamento para 32 ou 64 bits só acontece quando o valor é gravado na memória. O simulador do curso guarda os valores como reais de 64 bits (o `double` do JavaScript), então em contas muito longas os últimos dígitos podem diferir de um 8087 de verdade. Para os programas deste curso a diferença não aparece.
:::

## Os tipos de dados

O 8087 entende sete formatos na memória. Os reais se declaram com um **ponto decimal** (o montador usa ponto, não vírgula):

| Declaração | Tamanho | Formato | Instruções | Faixa e precisão |
|------------|---------|---------|------------|------------------|
| `x DD 3.75` | 32 bits | real curto (*single*) | FLD, FST, FSTP | cerca de 7 dígitos, até 10^38 |
| `x DQ 3.75` | 64 bits | real longo (*double*) | FLD, FST, FSTP | cerca de 15 dígitos, até 10^308 |
| `x DT 3.75` | 80 bits | real temporário | FLD, FSTP | cerca de 19 dígitos, até 10^4932 |
| `n DW -5` | 16 bits | inteiro | FILD, FIST, FISTP | −32.768 a 32.767 |
| `n DD 100000` | 32 bits | inteiro | FILD, FIST, FISTP | cerca de ±2,1 bilhões |
| `n DQ 5` | 64 bits | inteiro | FILD, FISTP | cerca de ±9,2 × 10^18 |
| `n DT 1234` | 80 bits | BCD compactado | FBLD, FBSTP | 18 dígitos decimais |

Repare que **DD** e **DQ** servem tanto para inteiros quanto para reais: o que decide é se o número tem ponto decimal. `DD 100` grava o inteiro 100 (64h 00h 00h 00h); `DD 100.0` grava o real 100,0 (00h 00h C8h 42h). E é a instrução que diz como os bytes são lidos: `FLD` lê um real, `FILD` lê um inteiro.

:::atencao FLD numa variável inteira
`FLD n` com `n DW 5` é erro de montagem: não existe real de 16 bits. Com `n DD 5`, o montador aceita (é um "real de 32 bits"), mas os bytes 05h 00h 00h 00h interpretados como real dão um número minúsculo, perto de 7 × 10^-45. Inteiro se carrega com **FILD**. Se o tamanho não for claro, como em `FLD [BX]`, diga com `DWORD PTR`, `QWORD PTR` ou `TBYTE PTR`.
:::

## Carregar e gravar

| Instrução | Faz |
|-----------|-----|
| `FINIT` | Reinicia o 8087: pilha vazia, sem exceções, arredondamento ao mais próximo. Use no começo. |
| `FLD x` | Empilha o real `x` (DD, DQ ou DT). `FLD ST(i)` empilha uma cópia de ST(i). |
| `FILD n` | Empilha o inteiro `n` (DW, DD ou DQ), convertido para real. |
| `FST x` | Grava ST(0) em `x` (DD ou DQ) **sem** desempilhar. |
| `FSTP x` | Grava ST(0) em `x` (DD, DQ ou DT) **e** desempilha. |
| `FIST n` / `FISTP n` | Grava ST(0) como inteiro, **arredondado** pela palavra de controle. FIST aceita DW e DD; FISTP também DQ. |
| `FLDZ`, `FLD1`, `FLDPI` | Empilham 0, 1 e π com a precisão total do chip. Também há `FLDL2T`, `FLDL2E`, `FLDLG2` e `FLDLN2` (logaritmos). |
| `FXCH ST(i)` | Troca ST(0) com ST(i). Sem operando, troca com ST(1). |
| `FFREE ST(i)` | Marca ST(i) como vazio. |

O primeiro programa: soma dois reais e grava o resultado. Execute passo a passo e acompanhe a pilha do 8087 (no laboratório, na aba **8087** da janela de inspeção).

```asm executar titulo="SOMA87.ASM: o primeiro cálculo com reais"
.MODEL SMALL
.8087
.STACK 100h
.DATA
a       DQ 1.5
b       DQ 2.25
soma    DQ ?
n       DW 10
dobro   DW ?
.CODE
inicio: MOV  AX, @DATA
        MOV  DS, AX
        FINIT               ; pilha vazia
        FLD  a              ; ST(0) = 1,5
        FLD  b              ; ST(0) = 2,25   ST(1) = 1,5
        FADD                ; ST(0) = 3,75   (soma e desempilha)
        FSTP soma           ; soma = 3,75, pilha vazia de novo

        FILD n              ; ST(0) = 10,0 (inteiro virou real)
        FADD ST, ST(0)      ; ST(0) = 20,0
        FISTP dobro         ; dobro = 20 (inteiro)
        FWAIT               ; espera o 8087 antes de o 8086 ler
        MOV  AX, dobro      ; AX = 20

        MOV  AX, 4C00h
        INT  21h
END inicio
```

A diretiva `.8087` diz ao montador para aceitar as instruções do coprocessador. No MASM ela é necessária; no simulador ela é aceita e não muda nada.

## As quatro operações e suas formas

`FADD`, `FSUB`, `FMUL` e `FDIV` têm várias formas. Todas operam com o topo da pilha:

| Forma | Exemplo | Faz |
|-------|---------|-----|
| memória | `FMUL x` | ST(0) = ST(0) × x (x real: DD ou DQ) |
| memória inteira | `FIMUL n` | ST(0) = ST(0) × n (n inteiro: DW ou DD) |
| `ST,ST(i)` | `FADD ST,ST(2)` | ST(0) = ST(0) + ST(2) |
| `ST(i),ST` | `FADD ST(2),ST` | ST(2) = ST(2) + ST(0) |
| com P | `FADDP ST(2),ST` | ST(2) = ST(2) + ST(0), depois desempilha |
| sem operandos | `FADD` | mesmo que `FADDP ST(1),ST`: soma os dois do topo e deixa só o resultado |

Subtração e divisão não são comutativas, então existem as versões **R** (*reversed*), que trocam a ordem:

```diagrama titulo="FSUB contra FSUBR"
   FSUB  x     ST(0) = ST(0) − x
   FSUBR x     ST(0) = x − ST(0)

   FDIV  x     ST(0) = ST(0) ÷ x
   FDIVR x     ST(0) = x ÷ ST(0)

   sem operandos, com a pilha  ST(0)=b  ST(1)=a :
   FSUB        a − b    (ST(1) − ST(0), desempilha)
   FDIV        a ÷ b    (ST(1) ÷ ST(0), desempilha)
```

O jeito mais fácil de pensar na forma sem operandos: empilhe `a`, empilhe `b`, e `FSUB` calcula **a − b**, na ordem em que você leu. É a notação polonesa reversa das calculadoras HP: "2 ENTER 3 −" dá −1.

Há ainda algumas operações de um operando só, sempre sobre ST(0):

| Instrução | Faz | Ciclos (aprox., 8087) |
|-----------|-----|-----------------------|
| `FCHS` | troca o sinal | 15 |
| `FABS` | valor absoluto | 14 |
| `FSQRT` | raiz quadrada | 180 |
| `FRNDINT` | arredonda para inteiro (pela palavra de controle) | 45 |
| `FSCALE` | ST(0) × 2^ST(1) | 35 |
| `FPREM` | resto parcial de ST(0) ÷ ST(1) | 125 |

:::cpu Quanto custa cada conta
Os tempos do 8087 variam com os operandos; os valores típicos são da ordem de 85 ciclos para `FADD`, 130 para `FMUL` entre registradores, 200 para `FDIV` e 180 para `FSQRT`, mais o tempo do endereço quando há operando na memória. O simulador usa valores típicos como esses, então trate a contagem de ciclos como aproximada. Para comparar: uma divisão de reais feita em software no 8086 levava milhares de ciclos.
:::

```quiz
? Com a pilha ST(0)=4 e ST(1)=10, quanto vale ST(0) depois de FDIV (sem operandos)?
- 0,4
+ 2,5
- 4, e ST(1) passa a valer 2,5
> A forma sem operandos é FDIVP ST(1),ST: calcula ST(1) ÷ ST(0) = 10 ÷ 4 = 2,5, grava em ST(1) e desempilha. O resultado fica no topo.

? Qual instrução carrega o inteiro de 16 bits `n DW 7` na pilha do 8087?
- FLD n
+ FILD n
- MOV ST,n
> FILD lê inteiros e converte para real. FLD só lê reais (32, 64 ou 80 bits), e MOV não alcança os registradores do 8087.

? Por que o MASM coloca o byte 9Bh antes de cada instrução do 8087?
+ É o WAIT: faz o 8086 esperar o 8087 terminar a instrução anterior
- É o prefixo que transforma a instrução em 32 bits
- É o código que liga o coprocessador
> No 8087, o sincronismo é responsabilidade do programa. O WAIT (9Bh) para o 8086 até o 8087 avisar que está livre, para que uma instrução nova não chegue enquanto a anterior ainda está em andamento.

? Depois de FLD a / FLD b / FLD c / FADD, quantos valores sobram na pilha?
- 1
+ 2
- 3
> Três FLD deixam três valores. O FADD sem operandos soma os dois do topo e desempilha um, então sobram dois: ST(0)=b+c e ST(1)=a.
```

## Imprimindo um número real

O DOS só imprime caracteres, e a nossa rotina `IMPRIMIR_NUMERO` só conhece inteiros. Para mostrar um real com duas casas decimais, o truque é transformar o problema num problema de inteiros:

1. Multiplique o valor por 100: 19,6349... vira 1963,49...
2. Grave como inteiro com `FISTP`: o 8087 arredonda para 1963.
3. Divida por 100 com `DIV`: o quociente (19) é a parte inteira, o resto (63) são os centavos.
4. Imprima o quociente, uma vírgula e o resto **sempre com dois dígitos** (5 centésimos é ",05", não ",5").

Para os dois dígitos, `AAM` é perfeita: com um valor de 0 a 99 em AL, ela deixa as dezenas em AH e as unidades em AL. Ela é assunto da aula de BCD, mas aqui ela já ajuda.

```asm executar titulo="AREA.ASM: área do círculo com duas casas decimais"
.MODEL SMALL
.8087
.STACK 100h
.DATA
raio        DD 2.5
area        DD ?
cem         DD 100.0
centesimos  DD ?            ; inteiro de 32 bits
msg         DB 'Area do circulo de raio 2,5: $'
.CODE
inicio: MOV  AX, @DATA
        MOV  DS, AX
        FINIT
        FLD  raio           ; r
        FMUL ST, ST(0)      ; r*r
        FLDPI               ; pi   r*r
        FMUL                ; pi*r*r
        FST  area           ; guarda (e mantém na pilha)

        MOV  AH, 09h
        LEA  DX, msg
        INT  21h
        CALL IMPRIMIR_REAL  ; imprime ST(0) e desempilha

        MOV  AX, 4C00h
        INT  21h

; IMPRIMIR_REAL: imprime ST(0) com 2 casas (-65535,99 a 65535,99) e desempilha
IMPRIMIR_REAL PROC
        PUSH AX
        PUSH BX
        PUSH DX
        FMUL cem                ; ST(0) = x * 100
        FISTP centesimos        ; inteiro de 32 bits, arredondado
        FWAIT
        MOV  AX, WORD PTR centesimos
        MOV  DX, WORD PTR centesimos+2
        TEST DX, DX
        JNS  @@positivo
        PUSH AX
        PUSH DX
        MOV  DL, '-'
        MOV  AH, 02h
        INT  21h
        POP  DX
        POP  AX
        NEG  DX                 ; DX:AX = -DX:AX (aula 22)
        NEG  AX
        SBB  DX, 0
@@positivo:
        MOV  BX, 100
        DIV  BX                 ; AX = parte inteira, DX = centésimos
        CALL IMPRIMIR_NUMERO
        PUSH DX
        MOV  DL, ','
        MOV  AH, 02h
        INT  21h
        POP  AX                 ; AL = centésimos (0..99)
        AAM                     ; AH = dezenas, AL = unidades
        ADD  AX, 3030h          ; os dois viram ASCII
        PUSH AX
        MOV  DL, AH
        MOV  AH, 02h
        INT  21h
        POP  AX
        MOV  DL, AL
        MOV  AH, 02h
        INT  21h
        POP  DX
        POP  BX
        POP  AX
        RET
IMPRIMIR_REAL ENDP

; IMPRIMIR_NUMERO: imprime AX (0..65535) em decimal. Preserva tudo.
IMPRIMIR_NUMERO PROC
        PUSH AX
        PUSH BX
        PUSH CX
        PUSH DX
        MOV  BX, 10
        XOR  CX, CX
@@divide:
        XOR  DX, DX
        DIV  BX
        PUSH DX
        INC  CX
        TEST AX, AX
        JNZ  @@divide
@@mostra:
        POP  DX
        ADD  DL, '0'
        MOV  AH, 02h
        INT  21h
        LOOP @@mostra
        POP  DX
        POP  CX
        POP  BX
        POP  AX
        RET
IMPRIMIR_NUMERO ENDP
END inicio
```

A saída é `19,63`. Repare em três detalhes:

- `FST area` grava **sem desempilhar**, porque o valor ainda vai ser impresso.
- O `FWAIT` antes do `MOV AX,WORD PTR centesimos`: é o 8086 lendo um resultado do 8087.
- `centesimos` é um **DD inteiro**: o `FISTP` numa variável DD grava um inteiro de 32 bits, que o 8086 lê em duas words.

--- enunciado
A variável **raio** (DW) chega com um raio **inteiro**. Calcule a área do círculo, π × raio², e guarde o resultado na variável real **area** (DD). Use `FLDPI` para ter π com toda a precisão do 8087.

.8087
.STACK 100h
.DATA
raio    DW 1

--- testes
[{ "nome": "raio 1: área π", "setup": { "raio": 1 }, "espera": { "reais": { "area": 3.14159265 } } },
 { "nome": "raio 10", "setup": { "raio": 10 }, "espera": { "reais": { "area": 314.159265 } } },
 { "nome": "raio 0", "setup": { "raio": 0 }, "espera": { "reais": { "area": 0 } } },
 { "nome": "raio 250", "setup": { "raio": 250 }, "espera": { "reais": { "area": 196349.540849 } } }]
--- dicas
O raio é inteiro: carregue com FILD, não com FLD.
FMUL ST,ST(0) eleva o topo ao quadrado.
FLDPI empilha π; depois, FMUL (sem operandos) multiplica os dois do topo e desempilha.
Termine com FSTP area, para gravar e deixar a pilha vazia.
--- solucao
.MODEL SMALL
.8087
.STACK 100h
.DATA
raio    DW 1
area    DD ?
.CODE
inicio: MOV  AX, @DATA
        MOV  DS, AX
        FINIT
        FILD raio           ; r
        FMUL ST, ST(0)      ; r²
        FLDPI               ; pi    r²
        FMUL                ; pi*r²
        FSTP area
        MOV  AX, 4C00h
        INT  21h
END inicio
```

        FINIT
        FILD  celsius
        FIMUL nove
        FIDIV cinco
        FIADD trinta2       ; ST(0) = F
        FIST  fahr          ; arredondado, F continua na pilha
        FSTCW cw_antiga
        FWAIT
        MOV   AX, cw_antiga
        OR    AX, 0C00h     ; RC = 11: truncar
        MOV   cw_trunca, AX
        FLDCW cw_trunca
        FISTP fahrTrunc     ; truncado, pilha vazia
        FLDCW cw_antiga     ; devolve o arredondamento normal
        MOV   AX, 4C00h
        INT   21h
END inicio
```

:::resumo
- O 8087 é um processador à parte que lê o mesmo código que o 8086: suas instruções começam com ESC (D8h a DFh), e o WAIT (9Bh) sincroniza os dois. O MASM põe um WAIT antes de cada instrução do 8087; antes de o 8086 ler um resultado, ponha um `FWAIT` você mesmo.
- Os oito registradores formam uma pilha: ST(0) é o topo. `FLD`/`FILD` empilham, `FSTP`/`FISTP` desempilham. Equilibre a pilha; `FSTP ST(0)` descarta o topo.
- Reais se declaram com ponto decimal em DD (32 bits), DQ (64) e DT (80). Inteiros usam FILD/FIST; BCD usa FBLD/FBSTP.
- Formas das operações: memória, `ST,ST(i)`, `ST(i),ST`, com P, e sem operandos (opera ST(1) com ST(0) e desempilha). `FSUBR` e `FDIVR` invertem a ordem.
:::
