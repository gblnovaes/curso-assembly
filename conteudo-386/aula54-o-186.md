## Uma máquina nova para a trilha

Até a aula 53, todo programa rodou no 8086 do curso. A partir daqui, os exemplos e exercícios rodam numa **máquina 386**: um PC com um 80386, 8 MB de memória, tela de texto, teclado, relógio, disco rígido, uma BIOS e um DOS mínimo. É a mesma máquina do começo ao fim da trilha, do modo real até um kernel com processos.

E a sintaxe muda para a do **NASM**, que você conheceu na [aula 53](avancado:aula53). O montador do curso para o 386 gera os mesmos bytes que o NASM 2.16 (isso é conferido a cada mudança, com milhares de linhas de teste), então tudo o que você escrever aqui monta igual no seu computador com `nasm -f bin`.

Cada bloco de código desta trilha diz em que modo a máquina começa:

| Modo | Como o programa começa | Como termina |
|---|---|---|
| **com** | um .COM do DOS: carregado em 0700:0100, CS = DS = ES = SS, `org 100h` | `mov ax, 4C00h` / `int 21h` |
| **boot** | um disco: a BIOS lê o setor 0 para 0000:7C00 e salta para ele, com DL = 80h | `cli` / `hlt` |
| **pm32** | já no modo protegido de 32 bits, como um carregador moderno deixa (módulo 19 em diante) | `cli` / `hlt` |

Este é o primeiro programa da trilha. Aperte **▶ Executar aqui**: abre o painel da máquina, com o código à esquerda, os registradores de 32 bits à direita e a tela do PC embaixo.

```nasm executar titulo="OLA.COM: o primeiro programa em NASM"
; nasm -f bin ola.asm -o ola.com
        org 100h                ; um .COM começa no deslocamento 100h

        mov ah, 9               ; DOS: escreve uma cadeia terminada em $
        mov dx, msg             ; sem colchetes: o endereço de msg
        int 21h

        mov ax, 4C00h           ; DOS: termina o programa
        int 21h

msg:    db 'Ola do NASM!', 13, 10, '$'
```

Repare no que **não** tem: nem `.MODEL`, nem `SEGMENT`, nem `ASSUME`, nem `END`. O NASM monta as linhas na ordem em que aparecem e pronto. O `org 100h` só avisa que o primeiro byte vai parar no deslocamento 100h, para os endereços (como o de `msg`) saírem certos.

:::dica Os registradores de 32 bits no painel
O painel mostra EAX, EBX, ECX... mesmo num programa de 16 bits, porque a CPU é um 386. AX é a metade de baixo de EAX, como AL é a metade de baixo de AX. Por enquanto, olhe só os 4 últimos dígitos; o módulo 18 explica o resto.
:::

## O 80186, o processador que quase ninguém viu

Em 1982 a Intel lançou o **80186** (e o 80188, com barramento de 8 bits, como o 8088). A ideia não era um PC mais rápido: era um 8086 com os chips de apoio dentro, um processador para placas industriais, terminais e controladores. Ele trazia o próprio controlador de interrupções, temporizadores e controlador de DMA, só que **incompatíveis** com os chips que a IBM tinha posto no PC. Por isso quase não houve PC com 186 (o Tandy 2000 é a exceção famosa).

O que ficou do 186 foi o **conjunto de instruções**. Ele acrescentou um punhado de instruções que o 286, o 386 e todos os processadores x86 depois deles mantiveram. Em qualquer PC a partir do AT, você pode contar com elas.

| Instrução | O que faz | No 8086 era preciso |
|---|---|---|
| `push 1234h` | empilha um valor imediato | `mov ax, 1234h` / `push ax` |
| `pusha` / `popa` | empilha / desempilha os 8 registradores gerais | 8 PUSHs e 8 POPs |
| `imul ax, bx, 10` | AX = BX × 10, com sinal, três operandos | `mov ax, 10` / `imul bx` (e DX era estragado) |
| `shl ax, 4` | desloca por um imediato | `mov cl, 4` / `shl ax, cl` |
| `enter 8, 0` / `leave` | cria / desfaz o quadro de pilha | `push bp` / `mov bp, sp` / `sub sp, 8` |
| `bound ax, [lim]` | confere se AX está dentro de um par de limites | CMP, CMP e dois saltos |
| `insb`, `outsb` (e `w`) | lê / escreve cadeias numa porta de E/S | um laço com IN ou OUT |

## PUSH imediato, PUSHA e POPA

`pusha` empilha AX, CX, DX, BX, o SP **original** (o valor de antes do próprio PUSHA), BP, SI e DI, nessa ordem. `popa` desempilha na ordem contrária e **joga fora** o SP guardado: seria estranho restaurar SP de dentro da pilha.

```diagrama titulo="A pilha depois de PUSHA (SP começou em FFFEh)"
endereço   conteúdo
FFFCh      AX
FFFAh      CX
FFF8h      DX
FFF6h      BX
FFF4h      SP original (FFFEh)
FFF2h      BP
FFF0h      SI
FFEEh      DI          <- SP agora
```

É o jeito mais curto de uma rotina devolver todos os registradores como recebeu, e por isso aparece no começo de tratadores de interrupção:

```nasm executar titulo="PUSHA.COM: uma rotina que não estraga nada"
        org 100h
        mov ax, 1111h
        mov bx, 2222h
        mov si, 3333h
        push 'A'                ; parâmetro imediato: novidade do 186
        call letra
        add sp, 2
        ; AX, BX e SI continuam com 1111h, 2222h e 3333h
        mov ax, 4C00h
        int 21h

letra:  pusha                   ; guarda os 8 registradores gerais (16 bytes)
        mov bp, sp
        mov dl, [bp+18]         ; 16 do PUSHA + 2 do endereço de retorno
        mov ah, 2               ; DOS: escreve o caractere em DL
        int 21h
        popa
        ret
```

## IMUL com três operandos e deslocamento por imediato

O `imul` do 8086 só tinha a forma de um operando: multiplica AX por alguma coisa e põe o resultado em DX:AX. O 186 acrescentou `imul reg, r/m, imediato`: o destino é qualquer registrador, a fonte pode ser memória, e só a metade de baixo do produto é guardada. Se o produto não couber, CF e OF ficam em 1.

Os deslocamentos ganharam a forma com imediato: `shl ax, 4` em vez de carregar CL antes. E o 186 passou a usar só os 5 bits de baixo da contagem: `shl ax, 33` desloca 1 vez. O 8086 deslocava 33 vezes, de verdade, um bit por vez (e demorava 4 ciclos por bit).

```nasm executar titulo="CONTA.COM: endereço de um caractere na tela, sem MUL"
; deslocamento na tela de texto = (linha * 80 + coluna) * 2
        org 100h
        mov bx, 12              ; linha
        mov cx, 40              ; coluna
        imul di, bx, 80         ; DI = linha * 80
        add di, cx
        shl di, 1               ; * 2: cada caractere ocupa 2 bytes
        mov ax, 0B800h
        mov es, ax
        mov word [es:di], 1F2Ah ; '*' branco no fundo azul, no meio da tela
        mov ax, 4C00h
        int 21h
```

Repare em `[es:di]`: no NASM, o prefixo de segmento fica **dentro** dos colchetes.

```quiz
? O que fica em SP depois de pusha / popa, se SP valia FFFEh antes?
- FFEEh, porque POPA não restaura SP
+ FFFEh: POPA desempilha 16 bytes e descarta o SP guardado
- O valor que estava na pilha, seja qual for
- FFF0h
> POPA soma 16 a SP ao desempilhar os oito valores. O valor de SP que estava na pilha é ignorado, então SP volta a FFFEh pela própria desempilhagem.

? Depois de imul cx, bx, 1000 com BX = 100, quanto vale CX e o que acontece com DX?
- CX = 100000 e DX recebe a parte alta
+ CX = 86A0h (os 16 bits de baixo de 100000) e CF = OF = 1; DX não muda
- CX = 1000 e DX = 100
- dá erro de divisão
> A forma de três operandos guarda só a metade de baixo do produto no destino e não usa DX. 100000 = 186A0h não cabe em 16 bits, então CF e OF avisam o estouro.
```

## ENTER e LEAVE

Na [aula 52](avancado:aula52) toda rotina começou com `push bp` / `mov bp, sp` / `sub sp, n` e terminou com `mov sp, bp` / `pop bp`. O 186 transformou isso em duas instruções:

- `enter n, 0` faz `push bp`, `mov bp, sp` e `sub sp, n`.
- `leave` faz `mov sp, bp` e `pop bp`.

O segundo operando do ENTER é o **nível de aninhamento**, pensado para linguagens como Pascal, em que uma função dentro de outra enxerga as variáveis da de fora. Com nível maior que zero, o ENTER copia ponteiros para os quadros das funções de fora. Quase ninguém usa, e compiladores de C sempre usam 0.

```nasm executar titulo="FATOR.COM: quadro com variável local"
        org 100h
        push 5
        call fatorial           ; AX = 5! = 120
        add sp, 2
        mov ax, 4C00h
        int 21h

; int fatorial(int n) com um laço e uma variável local t
fatorial:
        enter 2, 0              ; [bp-2] = t
        mov word [bp-2], 1
        mov cx, [bp+4]          ; n
.laco:  mov ax, [bp-2]
        mul cx                  ; DX:AX = AX * CX (n! cabe em AX até n = 8)
        mov [bp-2], ax
        loop .laco
        mov ax, [bp-2]
        leave
        ret
```

:::cpu ENTER é mais lento do que as três instruções
No 286, `enter 2, 0` leva 11 ciclos; `push bp` / `mov bp, sp` / `sub sp, 2` levam 3 + 2 + 3 = 8. No 386 a diferença continuou: 10 ciclos contra 6. Por isso os compiladores usam LEAVE (que é rápido) e quase nunca ENTER. Instrução nova não quer dizer instrução mais rápida.
:::

## Cadeias em portas: INSB e OUTSB

`outsb` escreve o byte de DS:SI na porta DX e avança SI; `insb` lê da porta DX para ES:DI e avança DI. Com `rep`, viram um laço inteiro numa instrução. Num PC de verdade, isso serve para controladoras de disco: um setor de 512 bytes sai da controladora com `rep insw`, 256 palavras de uma vez. Você vai fazer exatamente isso no módulo 26.

A máquina do curso tem uma porta de depuração, a **E9h**: tudo o que se escreve nela aparece na caixa "Saída" do painel (o QEMU e o Bochs têm a mesma porta). É o jeito mais simples de um programa dizer alguma coisa quando ainda não existe DOS nem BIOS por perto.

```nasm executar titulo="E9.COM: uma frase inteira com um REP OUTSB"
        org 100h
        cld
        mov si, frase
        mov cx, fim - frase     ; o NASM calcula o tamanho
        mov dx, 0E9h
        rep outsb
        mov ax, 4C00h
        int 21h
frase:  db 'saiu pela porta E9h', 10
fim:
```

## BOUND

`bound reg, [mem]` compara o registrador com duas palavras na memória, o limite de baixo e o de cima. Se estiver fora, gera a **interrupção 5**. É uma checagem de índice de vetor em hardware.

```nasm fragmento titulo="Conferindo um índice antes de usar"
        bound bx, [limites]     ; INT 5 se BX < 0 ou BX > 9
        mov al, [tabela+bx]
        ...
limites: dw 0, 9
```

:::anos90 A tecla Print Screen e o BOUND
A IBM tinha posto a rotina da tecla **Print Screen** justamente na INT 5, ignorando que a Intel reservava esse vetor. Num AT, um BOUND fora dos limites imprimia a tela. Pior: a exceção do BOUND volta para a própria instrução, então o programa imprimia a tela de novo, e de novo. Por isso o BOUND nunca pegou no DOS. No modo protegido a história é outra: a INT 5 é só uma exceção, com tratador seu (módulo 20).
:::

## A diretiva cpu

O NASM aceita todas as instruções até as mais novas. Para garantir que um programa roda num processador antigo, diga o nível com `cpu`:

```nasm fragmento titulo="Recusando instruções novas demais"
        cpu 8086
        shl ax, 4               ; erro: shl com imediato só existe a partir do 80186
        cpu 186
        shl ax, 4               ; agora vale
```

O montador do curso explica qual processador cada instrução exige. Em exercícios que pedem "só 8086", a primeira linha é `cpu 8086`.

```quiz
? O que faz enter 6, 0?
- Reserva 6 palavras na pilha
+ push bp, mov bp, sp e sub sp, 6
- Entra num procedimento de nível 6
- Salta para o deslocamento 6
> O primeiro operando é o número de bytes de variáveis locais; o segundo, o nível de aninhamento, que em C é sempre 0.

? Para que serve rep outsb?
- Copiar uma cadeia de memória para memória
+ Mandar CX bytes de DS:SI, um por um, para a porta DX
- Ler CX bytes da porta DX
- Escrever na tela
> OUTS é a versão de cadeia do OUT. Com REP, repete CX vezes, avançando SI (ou recuando, com DF = 1).
```

## Exercícios

```exercicio
id: a54-1
titulo: Multiplicar sem MUL
nivel: 1
maquina: 386
modo: com
exigir: IMUL
proibir: MUL
--- enunciado
Calcule **AX = BX × 10 + CX** usando a forma de três operandos do IMUL. Os valores chegam em BX e CX, e o resultado cabe em 16 bits.
--- inicial
        org 100h
        ; AX = BX * 10 + CX

        mov ax, 4C00h           ; atenção: AH = 4Ch estraga AX
        int 21h
--- testes
[{ "nome": "7 * 10 + 3", "setup": { "bx": 7, "cx": 3 }, "espera": { "mem": { "resultado:w": 73 } } },
 { "nome": "1234 * 10 + 5", "setup": { "bx": 1234, "cx": 5 }, "espera": { "mem": { "resultado:w": 12345 } } },
 { "nome": "-5 * 10 + 0", "setup": { "bx": -5, "cx": 0 }, "espera": { "mem": { "resultado:w": -50 } } }]
--- dicas
imul ax, bx, 10 calcula AX = BX * 10.
O int 21h para terminar precisa de AH = 4Ch, que apaga AH. Guarde AX numa variável antes, chamada resultado: resultado: dw 0, e mov [resultado], ax.
--- solucao
        org 100h
        imul ax, bx, 10
        add ax, cx
        mov [resultado], ax
        mov ax, 4C00h
        int 21h
resultado: dw 0
```

```exercicio
id: a54-2
titulo: Uma frase pela porta E9h
nivel: 1
maquina: 386
modo: com
exigir: OUTSB
--- enunciado
Escreva o texto de `msg` (que termina com um byte 0) na porta **E9h** com um único `rep outsb`. Você precisa contar o tamanho: use um rótulo depois do texto ou percorra a cadeia até o 0.
--- inicial
        org 100h

        mov ax, 4C00h
        int 21h
msg:    db 'NASM no 386', 0
--- testes
[{ "nome": "escreve a frase", "espera": { "saida": "NASM no 386" } }]
--- dicas
CX = tamanho, SI = msg, DX = 0E9h e DF = 0 (cld).
Ponha um rótulo fim: logo depois da frase, sem o 0, e use mov cx, fim - msg. Ou deixe o 0 no fim e conte com msg_fim - msg - 1.
--- solucao
        org 100h
        cld
        mov si, msg
        mov cx, fim - msg
        mov dx, 0E9h
        rep outsb
        mov ax, 4C00h
        int 21h
msg:    db 'NASM no 386'
fim:    db 0
```

```exercicio
id: a54-3
titulo: Uma rotina que devolve tudo
nivel: 2
maquina: 386
modo: com
exigir: PUSHA
--- enunciado
A rotina **conta** recebe em SI o endereço de uma cadeia terminada em 0 e guarda o número de letras **'a'** minúsculas em `total`. Ela pode usar os registradores que quiser, mas tem que devolver **todos** (AX, BX, CX, DX, SI, DI e BP) com os valores de antes. Use PUSHA e POPA.
--- inicial
        org 100h
        mov si, texto
        call conta
        mov [ax_depois], ax     ; para o teste conferir AX
        mov ax, 4C00h
        int 21h

conta:
        ; conte os 'a' de [si] em total
        ret

texto:  db 'banana e abacaxi', 0
total:  dw 0
ax_depois: dw 0
--- testes
[{ "nome": "banana e abacaxi", "setup": { "ax": 4660, "bx": 22136, "cx": 39030, "dx": 4386, "di": 13107, "bp": 17476 }, "espera": { "mem": { "total:w": 6, "ax_depois:w": 4660 }, "preservar": ["bx", "cx", "dx", "di", "bp"] } },
 { "nome": "sem nenhum a", "setup": { "ax": 1, "bx": 2, "cx": 3, "dx": 4, "texto": [120, 121, 0] }, "espera": { "mem": { "total:w": 0, "ax_depois:w": 1 }, "preservar": ["bx", "cx", "dx"] } }]
--- dicas
pusha no começo e popa antes do ret.
Um laço: mov al, [si] / inc si / cmp al, 0 / je .fim / cmp al, 'a' / jne .laco / inc word [total].
--- solucao
        org 100h
        mov si, texto
        call conta
        mov [ax_depois], ax
        mov ax, 4C00h
        int 21h

conta:
        pusha
        mov word [total], 0
.laco:  mov al, [si]
        inc si
        cmp al, 0
        je .fim
        cmp al, 'a'
        jne .laco
        inc word [total]
        jmp .laco
.fim:   popa
        ret

texto:  db 'banana e abacaxi', 0
total:  dw 0
ax_depois: dw 0
```

```exercicio
id: a54-4
titulo: Quadro com ENTER e LEAVE
nivel: 2
maquina: 386
modo: com
exigir: ENTER LEAVE
--- enunciado
Escreva **maior3**: recebe três números com sinal na pilha (empilhados como num `maior3(a, b, c)` em cdecl) e devolve o maior em AX. Monte o quadro com `enter` e desfaça com `leave`. O programa principal já empilha, chama e guarda o resultado.
--- inicial
        org 100h
        push word [c]
        push word [b]
        push word [a]
        call maior3
        add sp, 6
        mov [r], ax
        mov ax, 4C00h
        int 21h

maior3:
        ret

a:      dw 0
b:      dw 0
c:      dw 0
r:      dw 0
--- testes
[{ "nome": "3, 9, 4", "setup": { "a:w": 3, "b:w": 9, "c:w": 4 }, "espera": { "mem": { "r:w": 9 }, "pilhaEquilibrada": true } },
 { "nome": "-1, -7, -3", "setup": { "a:w": -1, "b:w": -7, "c:w": -3 }, "espera": { "mem": { "r:w": -1 }, "pilhaEquilibrada": true } },
 { "nome": "o último é o maior", "setup": { "a:w": 100, "b:w": -200, "c:w": 300 }, "espera": { "mem": { "r:w": 300 }, "pilhaEquilibrada": true } }]
--- dicas
enter 0, 0 já basta (sem variáveis locais). a fica em [bp+4], b em [bp+6] e c em [bp+8].
Comparação com sinal: jge / jle.
--- solucao
        org 100h
        push word [c]
        push word [b]
        push word [a]
        call maior3
        add sp, 6
        mov [r], ax
        mov ax, 4C00h
        int 21h

maior3:
        enter 0, 0
        mov ax, [bp+4]
        cmp ax, [bp+6]
        jge .b
        mov ax, [bp+6]
.b:     cmp ax, [bp+8]
        jge .fim
        mov ax, [bp+8]
.fim:   leave
        ret

a:      dw 0
b:      dw 0
c:      dw 0
r:      dw 0
```

:::resumo
- A trilha agora usa NASM e uma máquina 386, nos modos com, boot e pm32. Os blocos dizem em que modo começam.
- O 80186 quase não foi usado em PCs, mas as instruções dele ficaram: PUSH imediato, PUSHA/POPA, IMUL de três operandos, deslocamento por imediato, ENTER/LEAVE, BOUND, INS/OUTS.
- `pusha` guarda os 8 registradores gerais; `popa` descarta o SP guardado.
- A porta E9h é a saída de depuração da máquina do curso (e do QEMU e do Bochs).
- `cpu 8086`, `cpu 186`, `cpu 286`... fazem o NASM recusar instruções novas demais.
:::
